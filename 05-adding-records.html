Object state — create vs save

The lesson's core insight: instantiation is not persistence.

ActionIn memory?In database?id?
t2 = Tour(...)✓✗None
t2.save()✓✓2 — assigned by Django at save time
.save() is analogous to the COMMIT statement in MySQL — you tell the database you're happy with the changes and want them stored. Without it, the object lives only in your shell session and vanishes on exit.

Quick check

Four questions — click an answer.

1. What exactly is the Django shell?

python manage.py shell opens IPython with your Django settings/apps loaded — letting you modify the database without much hassle.

2. t = Tour(...) then t shows id: None. Why?

Instantiation only creates the object in memory. The database — which owns the auto-increment counter — hasn't seen it, so no id exists until .save().

3. What does adding a __str__ method to the model change?

Without it you see <Tour: Tour object (1)>. __str__ is a special Python method for a friendly display string. Note: after editing models.py you must exit and re-enter the shell.

4. Which IPython feature was demonstrated with sum(range(...))?

%time is a magic function — special commands starting with % providing enhanced features not available in standard Python.
