## What we build in this lesson

- A new project: **Asian Tours Agency** management system (manage tours, destinations and bookings across Asia)
- Project name: `worldtour` · App name: `asiatoursagency`
- Goal: render our first page in the browser.

## 1. Setup (recap of lesson 2)

```bash
cd lesson2_django_app      # go to project location
pipenv shell               # activate the virtual environment
pipenv install django      # install Django inside the env
django-admin startproject worldtour
cd worldtour
python manage.py startapp asiatoursagency
```

- Activating the venv creates a **Pipfile** — like `config.json` or `Cargo.toml`:
  stores all dependencies, packages, Python version, etc.
  It's **autogenerated — don't touch it**.
- **Using `uv` instead?** Equivalent workflow — project untouched, only env management differs:
  ```bash
  uv init                                   # creates pyproject.toml
  uv add django                             # installs + updates pyproject.toml & uv.lock
  uv run django-admin startproject worldtour
  cd worldtour
  uv run python manage.py runserver         # no activation needed
  ```
  `pyproject.toml` + `uv.lock` play the same role as the Pipfile.
- A project can contain **as many applications as you want**
  (Asian tours, African tours, European tours…) — here just one for simplicity.

## 2. Files inside the app folder

| File | Purpose |
|---|---|
| `__init__.py` | Empty — Python's way to treat the directory as a **package**; lets you import the app's modules elsewhere |
| `admin.py` | **Register your app's models** with Django's admin panel → user-friendly interface to interact with the data model (dedicated chapter later) |
| `apps.py` | **Configuration class** for the application — `AsiatoursagencyConfig(AppConfig)` with `name = 'asiatoursagency'`. Stores app-specific settings; useful for pluggable apps (metadata / configuration hooks) |
| `models.py` | **The most important file** — define data models: each **class = a database table**, each **attribute = a database field** |
| `tests.py` | Unit tests for your application's functionality |
| `views.py` | **Request–response logic** — the **V** in MVT. Functions/classes receive web requests and return web responses; get data via models, delegate formatting to templates |
| `migrations/` | Migration files — how Django **stores changes to your models** (and thus the DB schema). Each file is **timestamped** with details of the changes. (Applying them: next lesson) |

## 3. Register the app in `settings.py`

In `INSTALLED_APPS` (top or bottom of the list — doesn't matter), two ways:

```python
# simple way
'asiatoursagency',

# proper way (instructor's preference) — via the config class in apps.py

```

## 4. First view — `views.py`

```python
from django.http import HttpResponse

def index(request):
    return HttpResponse('Asian Tours Agency')
```

- `HttpResponse` — when the client sends an HTTP request, the server sends back an HTTP response, and the page renders.
- The view receives `request` regardless of method — GET, POST, PUT, DELETE (the 4 most common).
  **If not specified, a request is a GET by default** (fetch/retrieve data).
- Returning a raw string works but **isn't the proper way** — the proper way is a `templates/` folder with `index.html` using the Django Template Language (coming in a later lesson).

## 5. App-level `urls.py` (created manually)

The project-level `urls.py` exists already, but **each application needs its own `urls.py`**, created manually inside the app folder:

```python
from django.urls import path
from . import views          # current directory → import views.py

urlpatterns = [
    path('', views.index),   # route + view: the two main arguments
]
```

- `urlpatterns` — list of all routes available in the application.
- `path(route, view)` — first arg: the **route** (empty string `''` = homepage); second arg: the **view** to trigger (`views.index`).

## 6. Wire the app into the project `urls.py`

Project-level `worldtour/urls.py`:

```python
from django.contrib import admin
from django.urls import path, include    # import include!

urlpatterns = [
    path('admin/', admin.site.urls),     # admin dashboard route (later chapter)
    path('', include('asiatoursagency.urls')),  # delegate to the app's urls.py
]
```

- `include()` pulls in the app's `urlpatterns` → its `views.index` → the HTTP response.
- On saving, notice **`db.sqlite3` gets auto-generated** in the project folder.

## 7. Run

```bash
python manage.py runserver    # must be in the folder containing manage.py
```

- Server on **localhost:8000** → renders *"Asian Tours Agency"*.
- Inspecting the page: it IS an HTML page (html/head/body tags) — but only text, since we returned a string instead of a template.

## Request flow recap (this lesson in one line)

```
browser → project urls.py --include()--> app urls.py --path('')--> views.index → HttpResponse
```
